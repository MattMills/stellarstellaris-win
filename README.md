# StellarStellars - Windows (+Linux?) edition

The goal of this project is to start building an enhanced version of StellarStellaris that can hook into Stellaris on multiple platforms, with the initial focus being Steam Windows, since that is the most heavily used version.

This is in a very early alpha stage, it currently doesn't do much of anything.

Currently supported in version v0.1.1-alpha:
 * Windows Steam (should support any current version)
 * Windows GOG (should support any current version)

## Current State

Currently works on WINDOWS, Steam or GOG. I will eventually add Linux support, I don't have any macs.

Game bugs patched:
 * Hull/Shield/Armor Regen overflow - Replaced fixed point calculations with double based calculations to eliminate ship regen overflow
 * Disapearing army outliner group - Fixed Armies dissapearing from outliner menu
 
Performance issues patched:
* Species-is-modifiable alert - Causes large lag spikes in late game with a lot of species/planets

Debug logging added:
 * CEvent::ExecuteActual
 * CEffect::ExecuteActual
 * CRandomInListEffect::ExecuteActual
 * CEveryInListEffect::ExecuteActual
 * COnActionDatabase::PerformEvent
 * Implemented but disabled (way too noisy) - CTrigger::ExecuteActual
 * Implemented but disabled (also too noisy) - CToken related code to investigate token init.

 in order to dump debug data to a new log file (stellarstellaris-debug.log in the normal directory [example file as of 9/14/2022 here](docs/example-stellarstellaris-debug.log.txt)).

## Lua scripting (in progress)

The patches are moving from C++ to Lua. stellar-injected.dll embeds LuaJIT with
[lua_sigmatch](https://github.com/MattMills/lua_sigmatch) (byte patterns) and
[lua_fnmatch](https://github.com/MattMills/lua_fnmatch) (stellar-fnmatch function signatures), and
after the C++ hooks it runs `lua/init.lua` from the directory of the DLL. Nothing is patched from
Lua yet: `lua/stellar/report.lua` logs where the functions the C++ patches target are in the
running build, found by their stellar-fnmatch signatures and by the C++ byte patterns, and whether
the instructions the assembly patches rewrite are still there.

| File | |
|---|---|
| `src/dll/lua.cpp` | the Lua state and the `stellar` module |
| `lua/init.lua` | the first script |
| `lua/stellar/targets.lua` | the functions the C++ patches target, with their C++ byte patterns |
| `lua/stellar/signatures.lua` | their stellar-fnmatch signatures, generated by `tools/make_signatures.lua` |
| `lua/stellar/report.lua` | the report |
| `tools/make_signatures.lua` | `luajit tools/make_signatures.lua lua/stellar/signatures.lua gog-4.5.2.sig gog-4.5.1.sig ...` (newest first, `.sig` files from stellar-fnmatch) |
| `tools/dry_run.lua` | `luajit tools/dry_run.lua stellaris.exe`: the fnmatch part of the report, on a file, outside the game |

The tools need the `fnmatch` module (`fnmatch.dll` / `fnmatch.so` from lua_fnmatch) on `LUA_CPATH`.

`require("stellar")` in the game:

| | |
|---|---|
| `log(...)` | like `print` (which also goes to the log): writes to stellarstellaris-debug.log |
| `suspend_threads()`, `resume_threads()` | every other thread of the game |
| `read(address, size)` | a string, or nil and a message for unmapped memory |
| `patch(address, bytes)` | writes code or read-only data, returns the bytes it replaced |
| `heartbeat` | set it to a function: called with the frame number every second |
| `module_base`, `module_path` | stellaris.exe |
| `application`, `application_base` | what the loader found (the CApplication object, the "augustus" string) |
| `dll_path`, `lua_dir`, `git_hash`, `process_id` | |

The LuaJIT FFI reads and writes memory directly. The Lua state belongs to the init thread; code
that calls into Lua from game threads (hooks, later) has to hold `stellar_lua_lock()`.

Analysing stellaris.exe for fnmatch takes a few seconds; the analysis is kept in `cache/` next to the
DLL, by md5, so it is done once per game version.

Building needs the submodules (`git submodule update --init --recursive`), a Rust toolchain
(https://rustup.rs, for lua_fnmatch) and a Visual Studio 2022 developer prompt (LuaJIT is built with
its `msvcbuild.bat`).

## Install/Using:

 Compiled windows executables are available in Github workflows/actions as build artifacts, download the zip file, extract it somewhere (keep the `lua` folder next to the DLL), start Stellaris and run stellar-loader.exe 

 This will load the DLL into the currently running game, it must be run every time the game is restarted to use it.

 NOTE: There is not currently any protection against loading the patch into game memory more than once at a time; this may cause weirdness.

## Compatibility:

Currently, there are no compatibility issues, the loader can be run at any time during a game, and can be removed by restarting the game without any issue (although obviously any patched bugs will return).
